Question 5b:
User programs cannot access kernel memory because kernel pages are mapped without the PTE_U bit set. This mechanism is enforced in hardware by checking PDE and PTE permission bits and blocking user-mode accesses.

Question 5c:
The operating system can support up to 256 MB of physical memory. This is because JOS directly maps physical memory into the virtual range starting at KERNBASE, which leaves only 256 MB of virtual address space for that direct physical mapping.

Question 5d:
If we have maximum amount of physical memory, the overhead would be around 772KB with small extras. The overhead consists mainly of the pages[] array (512KB), the page directory (4KB), and page tables (256KB), with small additional overhead for stack-related mappings.

Question 5e:
We transition to an EIP above KERNBASE at the jmp *%eax in entry.S after %eax is loaded with the relocated label. We can keep executing at a low EIP right after enabling paging because entrypgdir.c mapped both from 0 to 4MB and from KERNBASE to KERNBASE+4MB to the same physical of 0 to 4MB, so the next few instructions are still mapped. This transition is necessary because the kernel is linked to run at high virtual addresses, so after we enter C code with normal symbol addresses, we have to execute in the KERNBASE mapping.
